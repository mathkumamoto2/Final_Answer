# 本間さんの採点フィードバックに基づく受け入れ基準

元の課題説明（[課題1](ex1_web-scraping/explanation.md)・[課題2](ex2_docker_and_db/explanation.md)）と、レビューで指摘された以下の要件を対象とする。実行手順・提出済み成果物は [README.md](README.md) を参照。

## A. URL抽出と優先順位

- 店舗ページの「お店のホームページ」を第一優先とし、この項目がなければ「オフィシャルページ」（または「公式サイト」）を採用する。
- `href="#"` はリンク先URLではない。対象リンクに紐付いた `data-o`、`data-url`、`onclick` などの静的HTML情報から復元する。
- URLが静的に特定できなければ `UNRESOLVED_LINK` として扱い、推測による補完や無関係なURLへの置き換えはしない。
- 掲載済み優先URLの接続に失敗してもURLを保持し、下位候補の公式ページへ安易に切り替えない。

## B. 店舗への直接メール

- 「お店に直接メールする」に対応する `mailto:` または同じラベル内に明記されたメールアドレスのみ採用する。
- JSON-LDにある `email` や、先頭にある無関係な `mailto:` を代用しない。
- 正例・負例の両方を回帰テストする。

## C. 掲載URLと接続・SSL検証

- 掲載された外部URLと接続・TLS・HTTPの確認結果を分ける。
- HTTPS接続の証明書検証が成功すれば、HTTP 404などのHTTPエラーとは独立にSSLを評価する。
- 証明書エラーは `TLS_ERROR`、確認不能・タイムアウトは `UNVERIFIED` として原因をログへ残し、掲載URLを保持する。
- CAPTCHAやぐるなび中継URLは保存せず、アクセス制限の回避を行わない。
- 別ドメインへ転送される場合は、店舗名または具体的な住所で同一店舗のサイトと確認できなければ転送先を採用しない。
- 公式サイトURLがそもそも掲載されていない場合は、URL・SSLを空欄とする。

## D. 一貫性・再現性

- 1-1はRequestsを使い、1-2はSeleniumで一覧の次ページをクリックする。
- 1-1と1-2は共通の `shared.gnavi_rules` / `shared.site_verifier` により抽出・判定基準を揃える。
- 2-2は1-1の `collect()` を再利用し、MySQLのDB `ex2`・テーブル `ex2_2` に保存する。
- 1-1・1-2は50行・指定9列・店舗名重複なし。2-2は `COUNT(*)` と `COUNT(URL)` を区別し、9列の保存値を照合する。
- 第三者が再実行できるよう、環境構築・依存ライブラリ・コマンド・検証方法をREADMEに明記する。

## 2026-11-17に確認した結果

**以下は提出者環境の実行ログ、提出CSV、およびDB確認画像に基づく結果であり、すべての実サイトやPCでの実行成功を保証するものではない。**

| 1-2（Selenium） | 50件 / 9列 / URL 49件、次ページ遷移を確認 |

LIGNOSAの実サイト検証は**掲載されたURLとメールの抽出**に対するもの。接続先ドメイン自体のTLS成功を示すものではない。HTTPエラー、TLSエラー、robots.txt、CAPTCHAなどはモックを用いた回帰テストでも確認している。

**注記：** 元の課題1-2はChromeDriver同梱を要求しているが、現在の修正版は安全上の理由でSelenium Manager方式を採用している。形式面については採点者の確認が必要。
